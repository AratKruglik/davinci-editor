# Плагін Claude Code для DaVinci Resolve Studio — базовий список скілів

Статус: етапи 1, 2 і 3 реалізовані (версія плагіна 0.4.0). Оновлено: 2026-10-30.
Пов'язані документи:
- `claude/marker-color-system.md` — скіл `marker-edit` і система кольорів маркерів.
- `claude/track-layout.md` — скіл `track-layout` і базовий набір доріжок.
- `claude/split-edits.md` — скіл `split-edits`: J-кати і L-кати (завдання, ще не реалізовано).

## Для кого

Плагін передусім для власного воркфлоу (YouTube, відеоуроки українською). Але ним, імовірно, користуватимуться й інші люди з подібним флоу. Звідси правило: значення за замовчуванням налаштовані під мене (камери, частота кадрів, фірмовий стиль, MotionVFX, бібліотека звуків, кольори маркерів, набір доріжок), але всі вони винесені в конфіг плагіна, а не зашиті в скіли. Жодних особистих шляхів у коді.

## Середовище і що вміє API

- DaVinci Resolve Studio 21.1.1, macOS (Apple Silicon).
- На Mac уже встановлений сервер MCP для DaVinci Resolve (`run_script`, `generate_lut`, `update_dctl`, пошук по API). Скіли працюють через нього, новий сервер не потрібен.

Можливості API, на яких тримається дизайн:

| Задача | Що є в API | Наслідок |
|---|---|---|
| Колір | `ApplyGradeFromDRX`, `SetLUT` на ноду, `SetCDL`, `SetNodeEnabled`, вхідний колірний простір кліпу; створювати ноди і змінювати їхні параметри не можна | Кольорові скіли = шаблони DRX + автоматичне застосування і підстроювання (LUT/CDL) |
| Збереження грейду при порізці | Remote-версії грейду (`AddVersion(..., 1)`, прив'язані до кліпу в media pool), Color Groups з pre/post-clip графами, `CopyGrades` | Грейд, зроблений до порізки, переходить на новий таймлайн |
| Depth Map | Працює через DRX-шаблон, ручні штрихи не потрібні | Автоматизується повністю |
| Magic Mask | Потрібні ручні штрихи | Не автоматизується повністю |
| Voice Isolation | `SetVoiceIsolationState` на кліпі й доріжці, сила 0–100 | Повністю |
| Гучність кліпу | Властивість `AudioVolume` елемента таймлайну | Рівні звуку й музики виставляються скриптом |
| Транскрипція | `TranscribeAudio`, `GetTranscription` (кожне слово з таймкодом), мова — параметр проєкту `transcriptionLanguage`; українська доступна через extended-налаштування | Основний спосіб — вбудована транскрипція DaVinci |
| Склейка | `AppendToTimeline` з `startFrame`/`endFrame`/`trackIndex`/`recordFrame`/`mediaType` | Монтаж за текстом збирається в новий таймлайн; звуки й музика ставляться на свої доріжки в точні місця |
| Доріжки | `AddTrack` (тільки зверху), `DeleteTrack`, `SetTrackName`, `SetTrackLock`, `SetClipColor`; колір заголовка доріжки й перенесення кліпів між доріжками недоступні | Структура доріжок за ролями; колір — через кліпи і шаблон `.drt` |
| Маркери | Маркери на кліпі в media pool, на таймлайні й на кліпі таймлайну: колір (16), назва, нотатка, тривалість, приховане `customData` | Монтаж за моїми маркерами; статус обробки без зміни моїх маркерів |
| Fusion | Повний API нод, параметрів, анімації; `InsertFusionTitleIntoTimeline`, `InsertFusionGeneratorIntoTimeline`, `AddTransition` (категорія `fusion`), `ImportFusionComp` | Motion-графіка генерується кодом; шаблони MotionVFX вставляються за назвою |
| Кадр для аналізу | `ExportCurrentFrameAsStill`, `GrabStill` | Claude може міряти колір на реальному кадрі |
| Color Match по таблиці | Вбудованого виклику в API немає | Корекцію за таблицею Claude рахує сам |

## Принцип кольорового конвеєра

Явні ноди замість автоматичного керування кольором DaVinci, щоб Claude завжди знав, у якому колірному просторі він міряє:

`CHART` (корекція за таблицею, лінійне світло / Apple Log) → `CST` (Apple Log → Rec.709) → `PRIMARY` (нейтральний баланс) → `SKIN` (кваліфаєр на шкіру) → `DEPTH` (розмиття фону, вимкнене в шаблоні) → `LOOK` (творчий look)

`ApplyGradeFromDRX` замінює все дерево нод, тому після першого застосування шаблону скіли змінюють його лише покроково: `SetLUT`, `SetCDL`, `SetNodeEnabled`. Старий шаблон без `SKIN`/`DEPTH` оновлюється на місці зі збереженням LUT таблиці.

Перед будь-якою зміною скіл робить копію таймлайну. Оригінал ніколи не редагується.

## Мій порядок роботи — скіл `edit-episode`

Оркестратор проганяє скіли саме в такому порядку і зупиняється після кожної стадії на моє затвердження. На кожній стадії він спершу читає мої маркери цієї стадії (див. `claude/marker-color-system.md`).

**Стадія A — колір до порізки.** Фарбую весь відзнятий матеріал до монтажу, щоб далі працювати з уже готовою картинкою.
`project-bootstrap` → `chart-match` → `log-to-rec709` → `natural-skin-grade` → `depth-background-blur`
Грейди зберігаються як remote-версії (прив'язані до кліпу в media pool) і через Color Groups по сценах, тому переживають порізку.

**Стадія B — «риба» і чорновий монтаж.**
`uk-transcribe` → `track-layout` (структура доріжок під цей епізод) → `text-based-cut` (вирізи на затвердження → новий таймлайн) → `dual-video-sync-pip` (для відеоуроків) → `split-edits` (J/L-кати там, де змінюється джерело картинки; заплановано)
Контроль: на новому таймлайні всі кліпи мають грейд; якщо ні — `CopyGrades` або повторне застосування шаблону.

**Стадія C — звук.**
`voice-isolation` → `sound-design` → `audio-effects` (за потреби) → `audio-finish`

**Стадія D — графіка, похідний контент, видача.**
`fusion-motion-graphics` → `tutorial-zooms` → `subtitles-uk` → `chapters-markers` → `shorts-cutdown` → `thumbnail-frames` → `pre-delivery-qc` → `deliver`
Перед перевіркою `track-layout` прибирає порожні доріжки; рендер — тільки після QC.

## Скіли

### Етап 1 — колір і монтаж за текстом (найбільша економія часу)

1. **`resolve-core`** (службовий) — підключення до Resolve, перерахунок кадрів і таймкодів, копія таймлайну перед змінами, пошук доріжки за роллю, спільні конвенції. Його використовують усі інші скіли.
2. **`log-to-rec709`** — Apple Log і Apple Log 2 у Rec.709: визначає профіль з метаданих кліпу, ставить CST-ноду з DRX-шаблону. Відкрите питання: чи є Apple Log 2 у списку колірних просторів 21.1.1; якщо ні — офіційний LUT від Apple.
3. **`chart-match`** — корекція за таблицею ColorChecker Classic 24: експорт кадру з таблицею без грейду (Apple Log) → декодування в лінійне світло → пошук патчів (OpenCV) → баланс білого й експозиція з сірого ряду + матриця 3×3 під еталонні значення → LUT/DCTL на ноду корекції → та сама корекція для всіх кліпів сцени → повторна перевірка з похибкою ΔE по кожному патчу. Кадр з таблицею позначається маркером Sand.
4. **`voice-isolation`** — вмикає AI Voice Isolation на доріжці Voice або на окремих кліпах із заданою силою.
5. **`uk-transcribe`** — вбудована транскрипція DaVinci українською (за потреби з розпізнаванням спікерів); забирає слова з таймкодами у JSON/SRT. Whisper — лише запасний варіант, якщо порівняння на реальному кліпі покаже, що DaVinci помиляється на термінах.
6. **`text-based-cut`** — знаходить невдалі дублі, обмовки, фальстарти, паузи, слова-паразити; враховує мої маркери Red/Green/Yellow (вони важливіші за автоматичні пропозиції); показує список вирізів на затвердження; збирає з нього новий таймлайн на доріжках A-roll і Voice.
7. **`marker-edit`** — монтаж за моїми маркерами і їхніми кольорами: читає маркери, будує план дій на затвердження, передає задачі відповідним скілам, статус пише в `customData`. В етапі 1 активні кольори Red, Green, Yellow і Sand; інші вмикаються разом зі своїми скілами. Повний опис — `claude/marker-color-system.md`.
8. **`track-layout`** — базовий набір доріжок за ролями: відео Backgrounds, A-roll, B-roll, Effects, Titles; аудіо Voice, SFX, Music. Кожна роль має свій колір. Додає доріжки за потреби (Screen, B-roll 2, Voice 2, Ambience, Subtitles UA), прибирає порожні після підтвердження. Повний опис — `claude/track-layout.md`.

### Етап 2 — якість картинки, звук, PiP і повний оркестратор

Як реалізовано (відхилення від первісного задуму):
- `natural-skin-grade`: кадр міряється на тимчасовій локальній версії, скрипт `skin_grade.py` рахує CDL; нейтральний баланс іде в `PRIMARY`, поворот шкіри до лінії скінтону (частково, `skin_strength`) — у `SKIN`. `GetCDL` в API немає, тому перевірка — повторний експорт кадру і вимір.
- `depth-background-blur`: AI CineFocus або Depth Map + Lens Blur живуть у шаблоні вимкненими, скіл їх вмикає і ставить кеш ноди. Сила `light`/`strong` — окремий DRX на пост-кліп граф Color Group (він не стирає грейд кліпу). Параметри ефектів API не задає, тому користувач один раз налаштовує ноду за чеклістом у скілі (точка фокусу, Skip foreground blur; для Depth Map — key-з'єднання, Invert, вимкнене превʼю). Rack focus потребує ключових кадрів, тож лишається ручним: скіл дає кроки.
- `motionvfx-catalog`: читає `.drfx` (zip) і `.setting`, збирає точні назви й текстові поля; працює як форкнутий помічник (`context: fork`).
- `dual-video-sync-pip`: синхронізація — `AutoAlignClips` за waveform; A-roll не змінюється, запис екрану і камера для PiP кладуться на доріжки Screen і PiP за планом `pip_plan.py`; PiP — через властивості трансформації кліпу. Ефекти MotionVFX API на кліп не накладає — лише вручну.
- `sound-design`: індекс власної бібліотеки (`sound_library.py`), ліцензії джерел музики підтверджуються один раз (`sound-licenses.json`); приглушення музики під голосом — розрізанням на секції з різною гучністю, бо ключових кадрів гучності в API немає.
- `audio-finish`: Dialogue Leveler, нормалізація голосу, опційний пресет Fairlight, рендер аудіо-міксу і вимір LUFS (`loudness.py`, BS.1770-4); загальна підтяжка гучності без кліпінгу.
- Усі скіли, що змінюють проєкт, мають хук `PreToolUse` (`guard.py`): скрипт з видаленням/скиданням викликає запит дозволу.

9. **`natural-skin-grade`** — базовий грейд, що береже скінтон: шаблон нод (баланс, експозиція, ізоляція шкіри, обмеження насиченості) + аналіз кадру відносно лінії скінтону на векторскопі → підстроювання CDL.
10. **`depth-background-blur`** — DRX-шаблон Depth Map + розмиття з налаштуванням сили; порівняти з AI CineFocus (Resolve 21).
11. **`motionvfx-catalog`** — опис встановлених титрів, переходів і генераторів MotionVFX (точні назви, категорії, параметри). На нього спираються інші скіли.
12. **`dual-video-sync-pip`** — синхронізація двох відео (камера + запис екрану) за звуком (розрахунок зсуву, розстановка кліпів на Screen і A-roll) + картинка в картинці через MotionVFX. Потрібна швидка перевірка, як накладаються PiP-шаблони MotionVFX через API; запасний варіант — вбудований ефект Picture in Picture у Resolve 21.
13. **`project-bootstrap`** — новий проєкт за шаблоном: параметри таймлайну (горизонтальний або вертикальний), структура бінів, імпорт, проксі, налаштування кольору й мови транскрипції.
14. **`sound-design`** — атмосферний саунд-дизайн. Читає транскрипт, структуру таймлайну і мої маркери Lavender/Sky, знаходить моменти для звуків (переходи, появи титрів, акценти, зміни сцен) і настрій кожної частини для музики. Пропонує cue sheet (час, тип звуку, настрій музики) на затвердження. Підбирає файли з проіндексованої бібліотеки (теги, настрій, темп, тривалість) і ставить їх на доріжки SFX, Music і Ambience з базовими рівнями. Відкрите питання: джерела звуків і музики та їхні ліцензії для YouTube (Content ID).
15. **`audio-finish`** — вирівнювання гучності діалогу, пресети Fairlight, нормалізація під YouTube (-14 LUFS), приглушення музики під голосом.
16. **`edit-episode`** (оркестратор) — мій порядок роботи: колір до порізки → «риба» і чорновий монтаж → звук. Опис стадій — у розділі вище. Перша версія з'являється після етапу 1 (стадії A і B частково), повна — після етапу 2.

### Етап 3 — графіка, похідний контент, видача

Як реалізовано (відхилення від первісного задуму):
- Спільна основа: дамп таймлайну (`resolve-core/reference.md`, розділ Timeline dump) і `timeline_map.py` — слова транскрипту переводяться в кадри змонтованого таймлайну і назад (діапазон таймлайну → діапазони вихідних кліпів). Береться живий дамп, а не `plan.json`, бо після рібкату я можу ще підрізати.
- Fusion: API не має анімації в Inspector (лише статичні `SetProperties`), тому титри й зуми будуються Fusion-композиціями зі специфікації JSON; ключові кадри — кожен кадр з кривої easing, щоб рух не залежав від сплайнів Fusion. Один спільний «будівельник» специфікацій.
- `fusion-motion-graphics`: плашки, виноски, кінетичні фрази, лічильники (вираз Fusion на `StyledText`) у фірмовому стилі з конфігу (Montserrat Bold, білий / #FFD400 / чорна плашка 70 %); плашка — елемент Text+ «Border», тож розмір підлаштовується під текст. Обрізати елемент таймлайну API не вміє: довжина = налаштування *Standard generator duration*, анімація згасає всередині композиції.
- `tutorial-zooms`: наближення в Fusion Transform (Inspector-трансформ PiP не чіпається), фокус обмежений так, щоб не було чорних країв, близькі зуми переходять панорамою; режим `punch-in` ховає джамп-кати статичним збільшенням через кадр.
- `subtitles-uk`: вбудовані субтитри Resolve (`CreateSubtitlesFromAudio`) не мають української — SRT будується з транскрипту (42 символи, 2 рядки, 17 символів/с, без висячих прийменників). Анімовані субтитри Shorts — одна Fusion-композиція на Titles; підсвітка слова — акцентна копія фрази з Write On на поточному слові (запасний варіант — фраза без підсвітки).
- `shorts-cutdown`: Shorts збираються з вихідного матеріалу (не вкладений таймлайн), `scaleToCrop` + Smart Reframe з перевіркою обличчя на кадрах; звук і субтитри — тими самими скілами.
- `chapters-markers`: правила YouTube перевіряє скрипт; скіли youtube-timestamps / youtube-seo-architect — необов'язкове продовження, якщо встановлені.
- `thumbnail-frames`: серія з 5 кадрів навколо моменту (проти моргання), титри й субтитри вимикаються на час експорту, скрипт відсіює розмиті й погано експоновані, решту Claude оцінює на око.
- `pre-delivery-qc`: лише читає і ставить маркери Cream; гучність — тим самим виміром, що й `audio-finish`.
- `deliver`: H.265 Main10 (апаратний енкодер Apple Silicon), 60 Мбіт/с для 4K, 20 для Shorts; у черзі лише власні завдання; файл перевіряється на диску (`mp4_info.py`: тривалість, розмір, кодек, звук).


17. **`fusion-motion-graphics`** — Claude сам будує Fusion-композиції (плашки з іменами, виноски, кінетична типографіка, лічильники) на доріжці Titles; фірмовий стиль у конфігу; правила плавності й таймінгу в скілі.
18. **`tutorial-zooms`** — наближення на потрібну ділянку екрану у відеоуроках.
19. **`subtitles-uk`** — SRT з транскрипту + анімовані субтитри для Shorts.
20. **`shorts-cutdown`** — пошук фрагментів на 30–60 с у транскрипті, вертикальний таймлайн, Smart Reframe.
21. **`chapters-markers`** — маркери розділів з передачею в скіли youtube-timestamps і youtube-seo-architect.
22. **`thumbnail-frames`** — кадри-кандидати для обкладинки в youtube-thumbnail-strategist.
23. **`pre-delivery-qc`** — перевірка перед рендером: офлайн-медіа, зайві поодинокі кадри, дірки, перевантаження звуку, гучність, порожні доріжки.
24. **`deliver`** — пресети рендеру YouTube 4K і Shorts, черга рендеру.

### Заплановано

25. **`split-edits`** — J-кати і L-кати: тільки на склейках зі зміною джерела картинки (камера ↔ екран, B-roll з живим звуком, зміна дубля чи кліпу, двоє спікерів, межа розділу); жорсткі перевірки, щоб не прозвучало вирізане; маркери Cocoa з нотаткою `J`/`L`. Повний опис — `claude/split-edits.md`.

### Поза планом

26. **`audio-effects`** — п'ять прийомів саунд-дизайну з відео «5 Sound Design Effects in DaVinci Resolve»: пісня «наживо» в сцені (EQ + Reverb), трохи простору для надто чистих SFX (Reverb), панорама за об'єктом, що перетинає кадр, Music Remixer, щоб вокал пісні не заважав голосу, Expander проти фонового шуму. API не має сеттерів EQ, ефектів, Music Remixer і Dynamics та ключових кадрів панорами, тому EQ і ефекти копіюються `CopyAttributes` зі зразкових кліпів на таймлайні `Audio FX Templates` (доріжки `LIVE`, `ROOM`), стартова панорама — `AudioPan`, решта — точні ручні кроки.

## Що перевірити на запущеному Resolve

- Точне значення `transcriptionLanguage` для української і чи extended — окремий параметр.
- Чи є Apple Log 2 серед вхідних колірних просторів.
- Як PiP-шаблони MotionVFX накладаються на кліп через API (`ImportFusionComp` / вставка `.setting`).
- Чи новий таймлайн, зібраний через `AppendToTimeline`, підхоплює remote-версію грейду автоматично.
- Чи можна призначити окрему гарячу клавішу на кожен колір маркера.
- Етап 3: ідентифікатори входів Text+ (елемент Border, Write On `Start`/`End`), кадр початку композиції на кліпі, доріжка й довжина `InsertFusionCompositionIntoTimeline`, як SRT лягає на доріжку субтитрів, ключ H.265 і одиниці `VideoQuality`, на яких кліпах працює `SmartReframe`.
- Чи зберігає `.drt` кольори заголовків доріжок; куди саме `AddTrack` додає доріжку; чи зберігається зв'язок відео й аудіо при розстановці на A-roll і Voice окремими викликами.
- `split-edits`: `DeleteClips` на одному з залінкованих елементів, `AppendToTimeline` з `recordFrame` у порожнє місце, `GetLeftOffset`/`GetRightOffset`, `SetFades` на аудіо (список — `claude/split-edits.md`).

## Відкриті питання

- Звідки беруться звуки й музика для `sound-design` і яка в них ліцензія.
- Звідки брати B-roll для маркерів Fuchsia.

## Наступний крок

Перевірити на запущеному Resolve пункти зі списку runtime discovery (`resolve-core/reference.md`), насамперед ідентифікатори входів Text+ і Write On, кадр початку Fusion-композиції, розміщення SRT і ключ кодека H.265.
